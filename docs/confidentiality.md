# Что нельзя оставлять в документе

Документы уходят наружу: заказчику, технологическому партнёру, службе информационной безопасности, иногда в приёмочную комиссию с представителями нескольких организаций. Один адрес внутреннего стенда в приложении превращается в инцидент, а инцидент в объяснительную.

## Список для проверки перед отправкой

Наличие любого пункта блокирует отправку файла.

| Что ищем | Почему нельзя | Куда это переносится |
| --- | --- | --- |
| Внутренние доменные имена и FQDN стенда | Разведка инфраструктуры по одному документу | Лист готовности стенда |
| IP-адреса и подсети стенда | То же | Лист готовности стенда |
| Учётные данные: логины, пароли, токены, ключи | Прямая компрометация | Подстановки, значения задаёт испытатель |
| Имена системных служб и учётных записей сервисов | Помогает целевой атаке | Обобщённое описание роли |
| Серийные номера оборудования | Привязка к конкретной поставке заказчика | Спецификация к договору |
| ИНН, ОГРН, банковские реквизиты | Не нужны в техническом документе | Договорные документы |
| Реквизиты физических лиц: СНИЛС, паспорт, личные телефоны | Персональные данные | Не передаются в составе ПМИ |
| Формулировки со ссылкой на банковскую тайну и иные охраняемые сведения | Меняет режим обращения с документом | Отдельный канал по правилам заказчика |
| Фрагменты реальных данных заказчика в примерах | Режим доступа, персональные данные | Обезличенный или синтетический набор |
| Снимки экрана с боевыми данными | То же, плюс адреса и имена в шапке интерфейса | Скриншоты с тестового контура |

## Как проверять

Греп по телу документа и по всем приложениям. Отдельно по вставленным таблицам, отдельно по подписям к рисункам: там прячется чаще всего.

Скриншоты проверяются глазами. Греп их не берёт, а в шапке браузера обычно виден адрес стенда, в углу имя пользователя, в таблице боевые записи. Каждый снимок открывается и просматривается целиком, а не по превью.

Первый чистый результат грепа перепроверяется вручную. Греп, упавший на кодировке или локали, показывает «чисто» и на грязном файле.

## Параметры стенда

Всё, что описывает конкретную развёртку, живёт в отдельном документе, обычно в листе готовности стенда, и передаётся защищённым каналом по правилам заказчика. В ПМИ на него идёт ссылка по реквизитам, без содержимого.

Так документ остаётся пригодным для повторного использования: тот же ПМИ с другим листом готовности работает на следующем стенде.

## Обезличивание примеров

В публичных и внутренних шаблонах примеры делаются нейтральными: `example.local`, `192.0.2.0/24` (этот диапазон зарезервирован под документацию по RFC 5737), пользователь `operator`, система «АС „Регистр“». Реальное название заказчика в пример не подставляется даже как «условное»: оно оттуда не вычищается никогда.

Если пример взят из живого проекта, из него убираются наименования сторон, адреса, идентификаторы записей и любые числа, по которым проект узнаётся.
